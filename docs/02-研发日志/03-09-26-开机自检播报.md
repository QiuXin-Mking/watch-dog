# 开机自检与状态播报语音

> 研发日志子需求 · 对应 Trellis 任务 `09-20-startup-selfcheck-broadcast`（已归档）
> 落地提交：`7995190`（2026-09-26 新增开机成功 + 8 段自检语音）、`8203c34`/`3b09e3e`（真实录音）、`94e5a08`（play_sounds.sh）· 相关文档：`docs/语音清单.md`
> 核心文件：`sounds/*.wav`（11 段）、`deploy/play_sounds.sh`

## Goal

为设备开机自检与状态播报提供完整语音资源：开机成功反馈、设备自检通过播报、分路故障播报（六目/左右腕断开恢复、电池充电异常、外接电源故障、屏幕故障），并提供一个顺序播放脚本用于板端听感验收；语音由 TTS 占位全部替换为真实录音。

## Background / 已确认事实

- 需求来源：Trellis 任务 `09-20-startup-selfcheck-broadcast`（prd.md + design.md + implement.md）。
- 自检编排与判定在 device-ui（`server.cjs`）完成，`watchdog` / `unified_capture` 只作事实源；语音资源统一放 `/etc/watchdog/sounds/`，device-ui 经 `playAnnouncement` 引用同一目录，不另建目录。
- 六目（jhh02 + jhh04）合并成一个播报项，与 watchdog 的 `sixcam` 通道口径一致。
- ES8323/I2S 播放链路要求双声道 frame slot：语音统一 44.1kHz 双声道 16-bit，保证播放速度/音调正常。

- 首批 8 段自检语音先以 TTS 占位（双目侧/四目侧断开恢复、设备自检通过、电池/屏幕/外接电源故障）落地联调，随后替换为真实录音。
- 屏幕故障、电池充电异常、外接电源故障、设备自检通过、开机成功等均录齐真实语音；双目侧/四目侧 4 段占位因六目已合并而移除。
- 全部语音统一 44.1kHz、双声道、16-bit PCM（新录音由 mono 24k 转 stereo 44.1k），文件名与文案逐字一致（含中文）。

### 顺序播放脚本 play_sounds.sh

- 依次播放 11 条自检播报语音，用于板端听感验收。
- 播放顺序：开机成功 → 六目断开/恢复 → 左腕断开/恢复 → 右腕断开/恢复 → 电池充电异常 → 外接电源故障 → 设备自检通过 → 屏幕故障。
- 支持指定目录（默认 `/etc/watchdog/sounds`），缺文件时跳过不中断。

## Key Decisions

1. **TTS 占位先行、真实录音后补**：先以统一格式占位联调播报链路，再逐条替换真实录音，链路联调不被录音排期阻塞。
2. **语音统一 44.1kHz 双声道 16-bit**：与 ES8323/I2S 双声道 frame slot 硬件要求对齐，从资源侧保证播放速度/音调正常。
3. **六目合并播报**：双目/四目合并为「六目摄像头」一个播报项，与 watchdog `sixcam` 通道口径一致，播报简洁不冗余。
4. **play_sounds.sh 顺序播放**：一条命令完整走查全部语音，板端听感验收/回归一键完成。
