# 语音合成流水线 — 用 edge-tts 生成播报 WAV

> 来源：`whale-live-bridge/docs/voice-pipeline.md`（鲸鱼娘直播桥接器的语音实现）。
> 本仓库只借用它的**离线合成链路**和两条硬约束（44.1kHz 双声道、峰值归一化），
> 不引入常驻 worker、缓存和播放器——watchdog 的播放是 C++/ALSA，见 `src/audio.cpp`。

## 一、定位

语音是**生成期资产**，不是运行期依赖：

```
开发机（联网 + Python）                    板端（无 Python/无网络）
文案 → edge-tts → MP3 → WAV  ──提交──→  sounds/*.wav ──deploy.sh──→ /etc/watchdog/sounds/
```

合成脚本：`tools/gen_voices.py`；产物：`sounds/*.wav`；部署：`deploy/deploy.sh`。

## 二、为什么必须是 44.1kHz 双声道

ES8323/I2S 播放链路要求双声道 frame slot。单声道数据会被按双声道 slot 消耗，
变成约 1.9 倍速、音调尖细（根因见 `docs/01-声音尖细根因.MD`）。

`src/audio.cpp` 现在加载时会把 mono 复制成双声道兜底，但**仍要求生成端统一输出
44.1kHz 双声道 16bit**：不依赖兜底路径，也避免采样率转换带来的额外变量。

## 三、链路

1. `edge_tts.Communicate(text, voice, rate, pitch)` 走微软在线朗读接口，得到 MP3；
2. `miniaudio.decode(..., nchannels=2, sample_rate=44100, SIGNED16)` 解码并重采样；
3. 峰值归一化：`gain = min(0.89 * 32767 / peak, 4.0)`，只放大不衰减；
4. 写 44 字节头的 PCM WAV（`wave` 模块）。
5. 回读校验采样率/声道/位深。

失败策略：单句瞬时断连重试 1 次（间隔 0.3s），再失败直接报错退出，不生成半截文件。

## 四、怎么生成

依赖装在**工作区外**，不污染项目：

```bash
python3 -m venv ~/.cache/watchdog-tts-venv
~/.cache/watchdog-tts-venv/bin/pip install edge-tts miniaudio
```

全量生成：

```bash
~/.cache/watchdog-tts-venv/bin/python tools/gen_voices.py
```

单条重生成（改文案后只替换一条）：

```bash
~/.cache/watchdog-tts-venv/bin/python tools/gen_voices.py --only 风扇故障.wav 过温.wav
```

换音色/语速（默认 `zh-CN-XiaoyiNeural`、`+0%`、`+0Hz`）：

```bash
~/.cache/watchdog-tts-venv/bin/python tools/gen_voices.py \
  --voice zh-CN-XiaoxiaoNeural --rate -5% --pitch +0Hz
```

重新部署到板端：

```bash
bash deploy/deploy.sh
```

## 六、格式与验收

| 项 | 值 |
|---|---|
| 容器 | WAV（PCM） |
| 采样率 | 44100 Hz |
| 声道 | 双声道 stereo |
| 位深 | 16-bit |
| 峰值 | 约 89%（0.89 FS），RMS 约 14% |

脚本生成后自动校验；板端可用 `deploy/play_sounds.sh` 顺序试听。

## 七、踩过的坑

- **单声道 → 1.9 倍速/尖细**：见第二节。生成端固定双声道。
- **合成音偏轻**：Edge 原始峰值中位数约 44%，不归一化在设备喇叭上听不清；
  固定归一化到 89%，并限制 4 倍增益（+12dB）防止抬噪。
- **不要无限重试**：播报场景 2 次仍失败就报错，避免卡住整批生成。
- **edge-tts 依赖微软接口**：签名算法会变，生成失败先 `pip install -U edge-tts`
  升级；这是生成期依赖，板端不受影响。
- **Python 中文输出**：脚本本身 UTF-8；在 Windows 终端跑需要
  `set PYTHONIOENCODING=utf-8`（Linux/WSL 无此问题）。

## 八、与上游文档的差异

上游为直播场景额外做了：常驻 Python worker、WAV 缓存、PowerShell `PlaySync`
同步播放、SAPI 离线兜底、12 秒预算掐断。这些**不需要搬到 watchdog**：

- watchdog 播放是 C++ 直接写 ALSA，阻塞到播完，天然可被 `cancel` 打断；
- 语音文件是固定集合，提交进仓库即可，不需要运行期合成/缓存；
- 板端不联网、不装 Python，减少一个故障面。
